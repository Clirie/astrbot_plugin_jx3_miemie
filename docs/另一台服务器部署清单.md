# 另一台服务器 · 部署清单

> 适用：把本插件部署到**第二台** AstrBot 服务器（如「策策」那台）
> 目标机器：任意 Linux + Docker 环境
> 参考环境（本机实测）：Debian 13 / Python 3.12.14 / AstrBot 4.28.1

---

## ⚠️ 先说两个最容易漏的坑

| 坑 | 后果 | 解决 |
|---|---|---|
| **没装中文字体** | 图上中文全变**方块** | `apt install -y fonts-noto-cjk` |
| **没装 Chromium** | 所有图片渲染失败 | `apt install -y chromium` |

这两个装一次就永久有效，**但新机器上十有八九是空的**。

## 一、环境要求

| 项目 | 要求 | 本机实测 |
|---|---|---|
| 系统 | Debian / Ubuntu / 任意 Linux | Debian 13 (trixie) |
| Python | ≥ 3.10 | 3.12.14 |
| AstrBot | ≥ 4.24.1 | 4.28.1 |
| **Chromium** | 必需（渲染用） | 153.0.8010.47 ✅ |
| **中文字体** | Noto CJK 系列 | 37 个 ✅ |
| 内存 | ≥ 2 GB（浏览器占用大） | 3.6 GB |

### 1.1 装浏览器与字体

```bash
apt update
apt install -y chromium fonts-noto-cjk
# 验证
chromium --version                    # 有版本号即可
fc-list :lang=zh | wc -l              # 大于 0 即可（本机 37）
```

### 1.2 装 Python 依赖

```bash
pip install playwright aiosqlite aiohttp jinja2 pillow fonttools pyyaml

# 只有系统没装 chromium 时才需要（会下载约 170MB）
python3 -m playwright install chromium
```

> 💡 本机已验证依赖全齐：playwright / aiosqlite / aiohttp / jinja2 /
> PIL / fontTools / yaml ✅

## 二、上传安装

1. 下载打包好的 zip
2. 后台 → **插件** → **安装插件** → 上传 zip
3. 找到「剑网三游戏数据查询工具」→ **启用**
4. **重载插件**（改了模板/代码必须重载）

> ⚠️ 插件名是 `astrbot_plugin_jx3_miemie`，与目标机器的目录名保持一致。

## 三、配置项（共 9 项）

后台 → 插件 → 配置，逐项填写：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `jx3api_token` | string | 空 | **必填**，JX3API 令牌 |
| `jx3api_ticket` | string | 空 | 推栏标识，部分接口需要 |
| `jx3api_wss` | string | `wss://socket.nicemoe.cn` | 事件推送地址 |
| `jx3api_wss_token` | string | 空 | 推送鉴权令牌 |
| `tls_verify` | bool | `true` | 建议保持开启 |
| `prefix` | object | `{enable:false, text:"剑三"}` | 指令前缀 |
| `team_management` | object | — | 团队管理面板设置 |
| `image_render_quality` | object | — | 出图质量（jpeg / 缩放）|
| `local_render_service` | bool | `true` | **自建渲染服务**（建议开）|

### ⚠️ 令牌千万不要两台共用！

```
两台机器同一个令牌 → 额度消耗翻倍（JX3API 按令牌计数）
```

**建议**：两台各用各的令牌。

## 五、三个注意事项

### 1️⃣ 数据不互通

两台机器的**避雷 / 团队 / 区服绑定**各自独立，**不会同步**。
（当前架构不支持跨机同步，需要的话要另行开发。）

### 2️⃣ 版本要同步

以后改了其中一台，**另一台必须手动更新**，否则：

- 指令数量不一致
- 行为不一致
- 排查问题时极易混淆

**建议**：每次打包后，**两台一起装**。

## 六、排错对照表

| 现象 | 原因 | 解决 |
|---|---|---|
| 后台找不到插件 | 未启用 | 插件列表里点启用 |
| 图上中文是方块 | **缺中文字体** | `apt install -y fonts-noto-cjk` |
| 所有图都失败 | 缺 Chromium | `apt install -y chromium` |
| 出图特别慢（10~40 秒）| 走了默认渲染服务 | 打开 `local_render_service` |
| 提示「猪脑过载」 | 渲染超时 | 检查渲染服务是否在线 |
| 指令没反应 | 没重载 / 群权限 | 重载插件；检查群消息权限 |
| 安装失败 | `metadata.yaml` 格式错 | 用官方校验过的包（本包已验）|

## 八、真实踩坑记录（2026-09-22 实战）

### 案例：机器人「只显示思考，不回复」

**现象**：发任何出图指令都没反应，QQ 里一直显示"思考中"

**排查过程**：

1. `docker logs` 里发现 QQ 接口报错：
   ```
   [botpy] 接口请求异常: 400, {'message': '富媒体文件格式不支持', 'code': 850019}
   ```
2. 检查渲染产物，发现存的"图片"其实是 151 字节的 JSON：
   ```
   {"code": 1, "message": "render error: BrowserType.launch:
    Failed to launch chromium because executable doesn't exist at /usr/bin/chromium"}
   ```
3. 结论：**容器内没有 chromium** → 渲染服务返回错误 JSON →
   插件误当图片发给 QQ → 平台拒收 → 重试 5 次后失败

**根因**：容器镜像里没有浏览器，而 `playwright` 也没有下载成功。

**修复**：

```bash
docker exec <容器名> bash -c "apt-get update && apt-get install -y chromium"
# 验证
docker exec <容器名> /usr/bin/chromium --version
```

**装完立即生效**（渲染服务每次启动浏览器时才查找路径，无需重启）。

**额外加固**（v1.1.0 起已内置）：插件会校验渲染产物是否为真图片，
不是则**当场报错**而不是把错误当图片发出去。

### 排查口诀

| 现象 | 先看哪里 |
|---|---|
| 只思考不回复 | `docker logs` 找 QQ 接口报错 |
| 提到"富媒体文件格式不支持" | 渲染产物坏了 → 查浏览器 |
| 提到 `BrowserType.launch` | **缺 chromium** |
| 提到"本地渲染服务不通" | 渲染服务没起来 |
